# 开发规范

> 项目：学生信息管理系统（JavaWeb 课程大作业）
> 维护人：组长 杨亮　｜　适用范围：全体组员、全部分支
> 规范的目的不是形式主义，而是避免五人协作时出现“参数对不上、页面取不到值、合并冲突”这三类返工。

## 1. 技术栈与环境（全组统一）

| 项 | 统一版本 | 说明 |
| ---- | ---- | ---- |
| JDK | **17**（Tomcat 11 最低要求） | 统一 Java 17 语法基线，不使用预览/实验特性，`pom.xml` 已设 `release=17` |
| 容器 | **Tomcat 11**（Jakarta EE 11 / Servlet 6.1） | 包名必须是 `jakarta.servlet.*` |
| 数据库 | MySQL 8.0，库 `student_db`，字符集 `utf8mb4` | 连接串见 `db.properties.template` |
| 构建 | Maven（项目自带 `mvnw` / `mvnw.cmd`，Maven 3.9.x） | 不要求本机装 Maven |
| 包命名空间 | `com.entity`、`com.dao`、`com.util`、`com.servlet`、`com.filter` | 组内已约定，禁止私自改根包 |
| 编码 | 全部 UTF-8（无 BOM） | Java、JSP、XML、SQL、md 一致 |

> ⚠️ **禁止混用 `javax.servlet` 与 `jakarta.servlet`**。网上大量教程是 Tomcat 8/9 的 `javax` 写法，
> 直接抄会 `ClassNotFoundException` / 编译不过。本项目统一 Jakarta。

## 2. 目录结构

```text
student_manage_javaweb
├── pom.xml
├── db.properties.template          # 配置模板（提交）
├── sql/student_db.sql              # 建库建表 + 测试数据
├── doc/                            # 小组文档（需求、数据库、接口、联调）
├── src/main/java/com/
│   ├── entity/                     # JavaBean（组长维护）
│   ├── util/                       # 工具类（组长维护）
│   ├── dao/ + dao/impl/            # 数据访问层（组长维护）
│   ├── servlet/                    # Servlet 控制器（各模块）
│   └── filter/                     # 过滤器（登录模块）
├── src/main/resources/db.properties   # 本地数据库配置（不提交）
├── src/main/webapp/
│   ├── WEB-INF/web.xml             # 部署描述符（组长维护）
│   ├── WEB-INF/error/              # 统一 404 / 500 错误页
│   ├── login.jsp / index.jsp       # 入口页
│   ├── admin/ 、 student/           # 管理员、学生页面
│   └── css/ 、 js/                 # 样式与前端校验
└── src/test/java/                  # 公共层集成测试（组长维护）
```

**新增文件放对位置**：Java 类放对应包；JSP 放 `admin/` 或 `student/`；静态资源放 `css/`、`js/`；
不要往项目根目录扔临时文件。

## 3. 命名规范

| 对象 | 规范 | 示例 |
| ---- | ---- | ---- |
| Java 类 | 大驼峰；实体用表名单数；DAO 接口 `XxxDao`，实现 `XxxDaoImpl` | `Student`、`StudentDaoImpl` |
| Java 方法 | 小驼峰动词开头 | `findByStuNo`、`updatePassword` |
| Java 常量 | 全大写下划线 | `ROLE_ADMIN` |
| 包名 | 全小写 | `com.dao.impl` |
| 数据库表 / 字段 | 表 `t_` 前缀 + 小写下划线；字段小写下划线 | `t_student`、`class_name` |
| JSP 页面 | 小写中划线，模块前缀 | `student-list.jsp`、`student-form.jsp` |
| Request 参数 | 小驼峰，见《DAO接口文档》§5.2 | `stuNo`、`className` |
| Session key | 小驼峰，统一 `loginUser` | `session.getAttribute("loginUser")` |
| Git 分支 | `feature/模块名` | `feature/login-filter` |
| 提交注释 | `【模块名】简要描述` | `【DAO层】新增分页查询与模糊搜索实现` |

**禁止**：类名/方法名用拼音（`xuesheng`、`chaxun`）；表字段用驼峰；页面参数各写各的（`stu_no` / `studentNo` / `id` 混用）。

## 4. 分层职责

| 层 | 职责 | 禁止 |
| ---- | ---- | ---- |
| JSP（视图） | 展示数据、表单、EL/JSTL 遍历 | 写 SQL、写业务判断、直接 `new DAO` |
| Servlet（控制器） | 收参、校验、调 DAO、放 request/session、转发/重定向 | 直接写 JDBC、拼 HTML |
| DAO（数据访问） | SQL、结果集映射、分页、条件拼装 | 处理 HTTP 对象、写业务提示语 |
| Entity（实体） | 承载数据，与表字段一一对应 | 放业务逻辑、放 DAO 方法 |
| Util（工具） | JDBC 连接与资源管理、通用方法 | 依赖 Servlet API |

调用方向只能是：JSP → Servlet → DAO → DbUtil → MySQL，不允许反向调用。

## 5. 编码规范

1. **缩进 4 空格**（Java、JSP、XML、SQL 统一），不用 Tab；行宽建议 ≤ 120 字符。
2. 每个 public 类、public 方法写 Javadoc（中文），说明参数、返回值、异常；关键 SQL 写行内注释。
3. 变量名见名知意；禁止 `a`、`b`、`temp1` 这类命名。
4. 异常不吞：`catch` 后至少记录日志或转成用户可读提示，禁止空 `catch`。
5. 字符串比较用 `"常量".equals(variable)`，避免 NPE；判空写全（null + 空串）。
6. 数据库连接对象只存在于方法内，**禁止**作为 Servlet 成员变量或放入 Session（并发下会串数据）。
7. 页面统一 UTF-8；表单提交方式：查询用 GET、写操作用 POST（修改密码、增删改）。

## 6. 数据库与 SQL 规范

1. 应用层**只允许通过 DAO** 访问数据库；Servlet / JSP 中出现 SQL 视为不合规。
2. 所有 SQL 用 `PreparedStatement` 占位符，**禁止**字符串拼接用户输入。
3. 模糊查询传原始关键字给 DAO，由 DAO 拼 `%...%` 并转义通配符。
4. 查询列显式写出，不用 `SELECT *`（表结构变更时不易察觉）。
5. 分页查询统一 `LIMIT ?, ?`，页码从 1 开始；总数与列表使用同一组条件。
6. 多步写操作使用事务，异常时 `DbUtil.rollback(conn)`；单条 SQL 不需要手动事务。
7. 数据库密码只写在本地 `src/main/resources/db.properties`（已 gitignore），**禁止**提交；
   `sql/student_db.sql` 中的测试数据密码不属于敏感信息，可以提交。

## 7. 权限与安全规范

1. 登录成功后把 `User` 对象放入 Session，key 统一为 `loginUser`；退出登录 `session.invalidate()`。
2. 权限判断必须在**服务端**做：Filter 拦未登录，Servlet 再判断角色和学号；
   页面上隐藏按钮只是体验优化，不能当作安全措施。
3. 学生只能访问 `loginUser.stuNo` 对应的本人数据；修改密码要校验 `oldPassword`。
4. 密码课程项目按明文存储，报告中需说明局限；不得把密码输出到日志、页面或 URL。
5. 统一错误页已配置（`WEB-INF/error/404.jsp`、`500.jsp`），不要把异常堆栈直接吐到页面。
6. 页面输出用户提交的内容时，用 `<c:out value="..."/>` 或 `${fn:escapeXml(...)}` 转义，防止 XSS。
7. 登录成功后先 `session.invalidate()` 再新建会话放入 `loginUser`，防止 Session Fixation。
8. 写操作（增删改、改密码）一律使用 POST；课程项目不要求实现 CSRF Token，
   但报告中应说明该风险，真实项目需补充校验。

## 8. Git 协作规范

1. `main` 为稳定分支，**任何人不得直接提交到 main**（包括组长）。
2. 每人一个 feature 分支（分支名见 README 分工表），开发完成后提交、推送、发起 PR。
3. 组长审核 PR，确认可运行后合并 main；组员合并后第一时间 `git pull origin main`。
4. 提交注释格式：`【模块名】简要描述`，一次提交只做一件事，禁止“一堆改动”混提。
5. 提交前检查：`git status` 中不应出现 `db.properties`、`target/`、`.idea/`、`*.class`。
6. 合并冲突时不要强推（`git push -f`），先本地拉取 main 解决冲突再推送。
7. 分支合并完成后不要立刻删除远程分支，等老师说验收结束再清理。
8. 仓库初始化阶段的首次提交由组长基于远端 `main` 完成，是本规范唯一的例外；此后所有人（含组长）一律走 feature 分支 + PR。

## 9. 文档与自测规范

1. 公共层接口变更必须同步更新 `doc/DAO接口文档.md`。
2. 每个模块完成后在 PR 描述中写：改动文件、自测步骤、截图（如页面模块）。
3. 提交前本地至少通过：`.\mvnw.cmd clean test`（无数据库时可跳过集成测试，但编译必须通过）。
4. 文档统一放在 `doc/`，命名 `xxx说明.md`；需求报告、答辩材料同样放 `doc/`，不散落在桌面或聊天记录里。
5. 集成测试会临时操作本地数据库（只创建/删除 `TEST` 前缀的测试数据，用例前后自动清理）；
   运行测试时不要同时手工修改演示数据。需求分析报告含个人姓名、学号，仓库为公开状态时不提交，单独归档提交。
