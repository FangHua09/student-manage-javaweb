# 数据库设计说明

> 项目：学生信息管理系统（JavaWeb 课程大作业）
> 数据库：MySQL 8.0　库名：`student_db`　字符集：`utf8mb4`　排序规则：`utf8mb4_general_ci`（显式指定）　存储引擎：`InnoDB`
> 脚本：`sql/student_db.sql`　维护人：组长 杨亮

## 1. 设计目标

1. 用最少的表覆盖系统全部业务：登录认证、角色区分、学生信息增删改查 / 条件查询 / 分页。
2. 学生信息与登录账号分离：`t_student` 存业务数据，`t_user` 存账号、密码、角色和关联学号，
   一个学生最多一个登录账号，管理员不关联学号。
3. 主键、唯一约束、外键、索引全部落到数据库层，不依赖应用层“自觉”。
4. 字符集统一 `utf8mb4`，支持中文姓名、班级、专业。

## 2. 实体关系

```text
t_student (1) ──── (0..1) t_user
   stu_no (PK)  ←──  stu_no (FK, UNIQUE, ON DELETE CASCADE ON UPDATE CASCADE)
```

- 一个学生最多绑定一个登录账号（`t_user.stu_no` 唯一）。
- 管理员账号的 `t_user.stu_no` 为 `NULL`（MySQL 唯一索引允许多个 NULL）。
- 删除学生时级联删除其登录账号，避免“孤儿账号”；删除账号不会影响学生记录。

## 3. 表结构

### 3.1 学生信息表 `t_student`

| 字段 | 类型 | 允许空 | 键 / 约束 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| `stu_no` | VARCHAR(20) | 否 | 主键 | 学号，业务主键 |
| `name` | VARCHAR(20) | 否 | 普通索引 `idx_student_name` | 姓名 |
| `gender` | CHAR(2) | 否 | 默认 `'男'` | 性别：男 / 女 |
| `class_name` | VARCHAR(30) | 是 | 普通索引 `idx_student_class` | 班级，如 `计科2401` |
| `major` | VARCHAR(30) | 是 | — | 专业 |
| `phone` | VARCHAR(15) | 是 | — | 联系电话 |
| `email` | VARCHAR(50) | 是 | — | 电子邮箱 |

- 索引 `idx_student_name`、`idx_student_class` 为等值查询、前缀查询与 `ORDER BY` 提供候选索引；
  本系统的模糊查询使用 `LIKE '%关键字%'`（前导通配符），**无法利用 B-tree 索引，会全表扫描**；
  课程项目数据量仅 100 条，全表扫描完全可接受，数据量增大后应改为前缀匹配或引入搜索引擎。
- 建表 SQL 见 `sql/student_db.sql` 第 20~31 行。

### 3.2 用户表 `t_user`

| 字段 | 类型 | 允许空 | 键 / 约束 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| `user_id` | INT | 否 | 主键，自增 | 用户主键 |
| `username` | VARCHAR(30) | 否 | 唯一索引 `uk_user_username` | 登录账号（管理员为 `admin`，学生为学号） |
| `password` | VARCHAR(64) | 否 | — | 登录密码（课程项目按明文存储，见 §6 安全说明） |
| `role` | TINYINT | 否 | 默认 `1` | `0` 管理员，`1` 学生 |
| `stu_no` | VARCHAR(20) | 是 | 唯一索引 `uk_user_stu_no`，外键 `fk_user_student` | 关联学号，管理员为 `NULL` |

- 外键：`FOREIGN KEY (stu_no) REFERENCES t_student(stu_no) ON DELETE CASCADE ON UPDATE CASCADE`。
- 角色编码与 Java 侧 `com.entity.User.ROLE_ADMIN / ROLE_STUDENT` 保持一致，禁止各处再手写魔法数字。

## 5. 初始化与重置

```powershell
# 方式一：PowerShell（不支持 < 输入重定向，用 cmd /c 包一层）
cmd /c "mysql -uroot -p --default-character-set=utf8mb4 < sql\student_db.sql"
```

```bat
:: 方式一（CMD）：命令行导入
mysql -uroot -p --default-character-set=utf8mb4 < sql\student_db.sql
```

> 方式二：Navicat 中右键数据库连接 → “运行 SQL 文件”，选择 `sql/student_db.sql`；
> IDEA Database 工具中直接打开脚本执行。注意 Navicat 不支持 MySQL CLI 的 `SOURCE` 命令，
> `SOURCE` 只用于 `mysql` 命令行客户端。

> ⚠️ 脚本包含 `DROP TABLE IF EXISTS t_user / t_student`，**会清空已有数据**。
> 只在首次建库或需要重置演示数据时执行；已有数据时请先备份。

导入完成后，把数据库账号密码写入 `src/main/resources/db.properties`（由 `db.properties.template` 复制而来，
该文件已被 `.gitignore` 忽略，不进入仓库）。

## 6. 设计说明与安全边界

1. **密码存储**：课程要求使用原生 JDBC，且测试数据密码为 `123456`，故当前按明文存储。
   真实项目应改为 BCrypt / SHA-256 加盐存储；README 中已注明该限制，答辩时需说明。
2. **SQL 注入**：应用层全部使用 `PreparedStatement` 占位符，DAO 层不拼接用户输入
   （模糊查询的通配符由 DAO 转义，见 `StudentDaoImpl#escapeLike`）。
3. **越权访问**：角色与学号校验必须在 Servlet 层基于 Session 再次判断，不能只靠页面隐藏按钮；
   数据库外键只保证引用完整性，不负责权限。
4. **编码**：连接串带 `characterEncoding=utf8`，库表 `utf8mb4`，页面统一 UTF-8；
   三处一致才能保证中文姓名、班级不乱码。
5. **审计字段**：本系统为课程项目，未设计 `create_time` / `update_time`。
   如后续需要记录修改时间，可扩展 `t_student.modified_at DATETIME`，并同步修改实体与 DAO。
